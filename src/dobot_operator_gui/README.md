# CR5、SC3000 与 SEER AGV 综合上位机

这是基于 ROS 2 Humble 和 `dobot_bringup_v3` 的 PyQt5 图形上位机，面向当前
CR5 + DH-AG95 + SC3000 + SEER AMB-300 配置。

## 功能

- 主界面按工作对象合并为五页：“连接、状态与日志”、“机械臂与DH-AG95”、
  “取点与点位运动”、“任务队列”和“SEER AGV综合控制”；机械臂/夹爪页及
  AGV综合页支持纵向滚动，连接状态和运行日志可用分隔条调整高度；
- 检查控制器 29999、30003、30005 端口及 ROS 2 驱动状态；
- 显示 RobotMode、六轴关节角和末端位姿；当控制器拒绝 Dashboard 的
  `GetAngle`/`GetPose` 查询时，自动使用 30005 发布的
  `/joint_states_robot` 和 `/dobot_msgs_v3/msg/ToolVectorActual` 实时反馈兜底，
  并在状态栏明确显示数据来源；
- 按设定负载使能、下使能、设置全局速度、读取并清除报警；
- 检查模式10和报警码后，由操作者确认是否执行 `Continue` 解除暂停；
- 分别选择是否临时关闭本体碰撞检测和电子皮肤（SafeSkin）后进入拖动模式，
  退出时恢复两项保护；
- 将当前关节角和笛卡尔位姿保存到 `~/dobot_ws/points`；
- 触发 SC3000 拍照，将六轴关节角、末端位姿、图像和采集元数据保存到同一个
  点位文件夹；
- 在取点页面以目标 5 FPS 显示 SC3000 实时画面；预览帧只经过 `/dev/shm`
  内存文件系统，显示后立即删除；
- 在实时画面中检测AprilTag、叠加三轴，并输出标签中心在相机坐标系下的
  X/Y/Z、RPY和重投影误差；
- 读取已有 `P1_joint.txt`、`P1_pose.txt` 等点位；
- 使用 `JointMovJ` 低速移动到选中点，轮询状态判断完成，不调用 `Sync`；
- 创建末端 RS485 Modbus 通道，初始化、开闭和读取 DH-AG95 状态；
- 组合AGV航点导航、点位运动、AprilTag 6D 到站纠偏、纠偏笛卡尔运动、夹爪动作、夹持力、
  初始化和等待指令，按任务队列顺序执行；
- 将任务队列保存为 JSON，之后可重新加载、调整顺序并再次执行；
- 显示AGV地图位姿、电池、急停、充电、控制权、报警及导航状态；
- AGV综合页只保留一张统一地图，同时绘制控制器地图、车体、官方站点、本地航点、
  各自朝向和规划路径；地图点击可选择填入重定位坐标或用户航点坐标；
- 可从控制器刷新地图、选择已存地图加载，并执行人工确认后的重定位；
- 在地图中显示官方站点和本地航点的车头朝向，按完整 `X/Y/Yaw` 导航回位；
- 按当前地图记录、更新和删除本地用户航点，执行控制器规划的点到点导航；
- 用 API 3053 预览“当前位置到官方站点”的站点序列；
- 选择LM站点执行最高 `0.08 m/s` 的安全门控导航；
- 提供按住运动的低速前进、后退和旋转，以及独立AGV停止/取消导航；
- 机械臂和AGV分别提供明确标注的停止入口。

## 启动

先在终端启动 Dobot ROS 2 驱动：

```bash
source /opt/ros/humble/setup.bash
source ~/dobot_ws/install/setup.bash
export DOBOT_TYPE=cr5
export IP_address=192.168.192.201
export DOBOT_FEEDBACK_PORT=30005
ros2 launch dobot_bringup_v3 dobot_bringup_ros2.launch.py
```

另开终端启动上位机：

```bash
source /opt/ros/humble/setup.bash
source ~/dobot_ws/install/setup.bash
ros2 run dobot_operator_gui dobot_operator_gui
```

也可以双击桌面上的“CR5·相机·AGV 综合上位机”。桌面入口不会启动或使能
机械臂；当 `192.168.192.5:19204` 可达且没有现存 `/seer_agv_node` 时，会启动
唯一的AGV驱动。AGV不可达不会影响机械臂、夹爪和相机页面。

启动器从 `ip route get` 自动识别AGV实际使用的有线接口，再检查该接口的物理载波
和状态端口，以避免VPN/透明代理造成端口探测假阳性。需要锁定接口时可在启动前设置
`SEER_AGV_INTERFACE`；AGV地址可用`SEER_AGV_HOST`覆盖。

## SEER AGV 集成边界

- GUI不连接AGV TCP端口，只使用 `/seer_agv/*` ROS话题和服务；
- `seer_agv_node` 是19204、19205、19206、19207的唯一连接所有者；
- 点动使用 `/seer_agv/cmd_vel`，TF使用
  `seer_map -> seer_base_link`，不会覆盖机械臂话题或坐标系；
- 当前Robokit `3.4.4.6` 只有 `reloc_status=1` 才允许运动，状态3会在3051或
  2010下发前被拒绝，必须先由操作员在AGV侧确认定位；
- 导航和点动互斥，状态过期、急停、充电、控制权抢占、阻挡、减速或报警都会
  关闭运动安全门。
- 用户航点保存在 `~/dobot_ws/agv_waypoints.json`，按当前地图名称隔离；它们不会
  上传、删除或覆盖Robokit地图中的官方站点。
- 加载地图使用API 2022，重定位使用API 2002，取消重定位使用API 2004；这些
  操作只在车辆静止且操作员逐次确认后执行。重定位结束不会自动调用API 2003，
  必须核对地图中的车体位置和朝向后再点击“确认定位正确”。
- 点动区同时显示驱动实际发送的速度和AGV反馈速度。若前进指令为正而实测速度
  为零、同时状态为`slowed=true`，说明前向安全区域正在拦截，必须清除障碍或
  检查前向安全传感器，不能从软件绕过。

## 推荐操作顺序

1. 启动 `dobot_bringup_v3`，再打开上位机。
2. 在“连接与状态”中确认驱动可用并读取 RobotMode。
3. 输入真实的末端总负载；确认工作区安全后使能。
4. 取点时进入拖动模式，到位静止后保存点位，最后退出拖动并恢复两项保护。
5. 点位运动前确认 Mode 5、低速参数以及整条运动路径无障碍物。
6. 夹爪页面依次执行“创建通道”“初始化夹爪”“读取状态”，再做开闭测试。
7. 在“任务队列”页添加指令、检查顺序并确认执行。AGV移动前必须先把机械臂收回
   安全运输姿态；包含夹爪指令时必须先创建 Modbus 通道，包含点位运动时机械臂
   必须处于 Mode 5。

## 安全设计

- 软件不会自动清除报警、使能机械臂、恢复暂停队列或执行历史命令。
- “安全解除模式10暂停”仍可能恢复旧运动队列，使用前必须在示教器确认任务来源。
- 关闭本体碰撞检测或电子皮肤、使能、点位运动和夹爪闭合均要求人工确认。
- 电子皮肤默认保持开启；只有确认电子皮肤误触发、工作区清空且有人现场监护时，
  才勾选临时关闭。`-3` 表示电子皮肤碰撞报警，清除前会显示专项警告。
- 进入拖动失败时程序会反向恢复已关闭的保护；退出拖动或关闭上位机时也会尝试
  开启电子皮肤并恢复选定的碰撞等级。通信失败时必须在示教器再次确认状态。
- 点位运动不使用阻塞式 `Sync()`，防止控制器队列异常时卡死 bringup 节点。
- 上位机记录到任一保护被关闭时，退出软件会给出警告并尝试恢复。
- 急停只负责向控制器发出急停请求，不能替代实体急停按钮和现场监护。
- ROS驱动可用时不会额外连接控制器TCP端口，避免干扰已有会话。
- 队列严格串行：机械臂到位、夹爪反馈完成后才进入下一步；任一步失败后，后续
  指令不会执行。
- “当前步骤后停止”用于安全停止后续步骤，不会中途切断正在运行的机械臂动作；
  需要立即停机时使用红色急停或实体急停。

### V3 电子皮肤服务

本工作区为原 V3 ROS 驱动补齐了缺失的 `SetSafeSkin` Dashboard 封装和 ROS 2
服务。`status=0` 临时关闭电子皮肤，`status=1` 重新开启：

```bash
ros2 service call /dobot_bringup_v3/srv/SetSafeSkin \
  dobot_msgs_v3/srv/SetSafeSkin "{status: 1}"
```

该服务与 `SetCollisionLevel` 相互独立。日常应保持 `status=1`；关闭电子皮肤会
失去非接触防护，不能把上位机自动恢复当作示教器状态确认或实体急停的替代品。

## 点位格式

仍沿用当前工作区格式：

```text
~/dobot_ws/points/P1_joint.txt
~/dobot_ws/points/P1_pose.txt
```

点名只允许字母、数字、点、下划线和连字符。保存使用临时文件原子替换，避免
程序中断后留下半个点位文件。

## 点位与 SC3000 图像成组采集

在“取点与点位运动”页面可以自行选择保存根目录。输入点名、确认 SC3000 IP
（默认 `192.168.192.11`），机械臂静止后点击“同步拍照并保存整组”。第一次使用
前需安装 FTP 依赖：

```bash
/usr/bin/python3 -m pip install --user pyftpdlib
```

上位机将按以下顺序执行：

1. 读取一次稳定的关节角和末端位姿；
2. 确保 FTP Server 监听 `2121`，通过 Modbus TCP `502` 触发 SC3000；
3. 等待相机通过被动端口 `30000:30009` 上传完整的新图；
4. 再读取一次稳定状态，并检查拍照前后最大关节变化不超过 `0.05°`；
5. 将整组数据写入临时目录，全部成功后再替换为最终目录。

例如选择 `${HOME}/dobot_dataset` 并保存点 `P1` 后得到：

```text
$HOME/dobot_dataset/P1/
├── P1_joint.txt
├── P1_pose.txt
├── P1_image.jpg
└── P1_capture.json
```

`P1_capture.json` 记录拍照前后状态、相机触发和收图时间、RobotMode、Modbus
状态寄存器以及最大关节漂移。图像触发被两次静止状态采样包围；这适合静止取点
和标定数据管理，但不代表相机曝光时刻与机械臂控制器达到硬件级同步。

## SC3000 实时预览

“取点与点位运动”页面左侧提供“开始预览”和“停止预览”。预览循环以 200 ms
为目标周期执行一次 Modbus 触发和 FTP 收图，并显示实测 FPS。SC3000 的标准
协议不是视频流，因此实际帧率仍取决于当前相机任务的曝光、算法执行和 JPEG
上传耗时；若单次周期超过 200 ms，界面会显示低于 5 FPS 的真实数值。

预览文件只短暂出现在：

```text
/dev/shm/dobot_operator_gui_sc3000
```

`/dev/shm` 是内存文件系统。每帧加载到界面后会立即删除，停止或退出上位机时
也会再次清理，不会写入点位目录或长期占用硬盘。点击“同步拍照并保存整组”时，
预览会暂时让出相机；这一帧按用户要求保存到点位文件夹，完成后自动恢复预览。

上位机需要独占 FTP 端口 `2121`。启动预览前请停止独立运行的
`sc3000_ftp_server.py`，否则界面会明确提示端口被占用。

## AprilTag实时定位

取点页面的SC3000预览区提供“AprilTag实时定位”开关，默认黑框外边长为
`58.5 mm`。现场标签已确认为 `tag36h11 ID=0`，因此界面默认选择
`tag36h11`以减少每帧检测时间；也可以切换为自动尝试
`tag16h5、tag25h9、tag36h10、tag36h11`，或指定ID。设置修改后停止并重新
开始预览，新参数才会进入预览线程。

每次检测会同时输出两个坐标系：

```text
相机坐标：X画面向右，Y画面向下，Z沿相机光轴向前；原点为相机光心
基座坐标：CR5 User0（默认用户坐标系，即机械臂基座坐标系）
目标点：AprilTag黑色正方形的物理中心
```

算法使用推荐SC3000内参、AprilTag四角、`SOLVEPNP_IPPE_SQUARE`和LM优化。
检测成功后，预览画面叠加标签外框、坐标轴和XYZ，界面同时显示family、ID、
相机XYZ/RPY、基座XYZ/RPY及重投影RMS。基座结果使用实时读取的
`GetPose(User=0, Tool=0)`和手眼标定文件
`~/dobot_ws/points/calibration_results/sc3000_cr5_handeye_first20.json`，按
`base_T_tag = base_T_tool0 × tool0_T_camera × camera_T_tag`计算。如果ROS位姿
服务暂时不可用，相机坐标仍会继续输出，基座行会明确显示失败原因。

同步拍照保存点位组时，该帧的两套坐标都会写入`点名_capture.json`的
`apriltag.detections`；其中每个检测的`xyz_mm/rpy_degrees`是相机坐标，
`base_pose.xyz_mm/base_pose.rpy_degrees`是CR5基座坐标，同时保存所用Tool0
位姿和手眼标定来源。原始点位图片保持无标注。

## DH-AG95 寄存器

- `0x0100`：初始化；
- `0x0101`：夹持力，20~100%；
- `0x0103`：目标位置，0闭合、1000打开；
- `0x0200~0x0202`：初始化状态、夹持状态和实时位置。

VX500 不得与 DH-AG95 并接占用同一末端 RS485 A/B 线路。

## 任务队列

支持以下指令：

- 导航到控制器官方站点（使用站点保存的朝向）；
- 导航到本地用户航点（保存完整 `X/Y/Yaw` 快照）；
- 移动到已保存点位（每一步独立保存全局速度、SpeedJ、AccJ 和到位容差）；
- 夹爪闭合比例，0% 为完全打开、100% 为完全闭合；
- 夹爪协议位置，0 为闭合、1000 为打开；
- 设置夹持力 20~100%；
- 初始化夹爪；
- 等待 0.1~3600 秒。

DH-AG95 是直线平行夹爪，协议没有“闭合角度”参数。上位机使用闭合百分比表示
行程，并自动换算为协议位置：`位置 = 1000 × (100 - 闭合百分比) / 100`。
队列文件默认保存在 `~/dobot_ws/queues/*.json`，加载时会严格校验格式和参数；
执行前还会验证队列引用的全部点位文件，避免执行到一半才发现点位缺失。
